# Parley — Architecture

> *Smalltalk packages, resolved by conversation.*

**Status:** Canonical. This document is the system-wide blueprint. Where code or discussion disagrees with this document, this document wins until it is amended. Detailed component specifications live in the three design documents ([domain-model.md](domain-model.md), [manifest-and-serialization.md](manifest-and-serialization.md), [resolver.md](resolver.md)); this document defines the system and its invariants.

**Project:** Parley — a modern, native command-line package manager for GNU Smalltalk, written entirely in Smalltalk, targeting the stable **GNU Smalltalk 3.2.5** baseline. CLI verbs: `parley init`, `parley install`, `parley resolve`, `parley update`, `parley exec`, `parley publish`.

---

## 1. Core Philosophy & Engine Hygiene

### 1.1 The Moat

The hero of this codebase is the idea of **live objects, clean message passing, and refactor-as-you-think**. Every part of the dependency pipeline is an independent domain object answering messages. There are no centralized procedural scripts, no "manager" god-objects, and no glue code that reduces the domain to data shuffled between functions. When logic grows conditional branches on the *kind* of thing it handles, that is the signal to introduce polymorphism, not more branching.

Parley is a self-contained, object-shaped domain. It depends only on the GNU Smalltalk 3.2.5 kernel and the bundled `gst-package` tooling. **No third-party library dependencies, ever** — including serialization libraries (see §2.4).

### 1.2 Engine Constraints (3.2.5 Reality)

Three platform facts shape the architecture and MUST NOT be fought:

1. **No in-image version isolation.** The namespace system cannot host two versions of the same class simultaneously. All dependency isolation is **process-level** (§5), never in-image. In-image version sandboxing is a platform impossibility, not an engineering challenge.
2. **Missing convenience protocol.** Methods such as `ifEmpty:` / `ifEmpty:ifNotEmpty:` do not exist on 3.2.5 collections. They are supplied via the compatibility layer (§1.3), never via scattered verbose workarounds.
3. **No STON or modern serialization.** All static artifacts use the **literal micro-format** (§2.4) with a purpose-built reader. Serialization NEVER round-trips through the compiler for third-party content.

### 1.3 Open-Class Hygiene (`*parley-compat`)

Modernizing extensions to kernel classes are permitted under strict rules:

- All kernel extensions live in a single method category: **`*parley-compat`**.
- The layer is **minimal**: only methods the codebase demonstrably uses, defined once, loaded at the project entry point.
- Extensions are **defensive**: selectors match well-known ANSI/Pharo semantics exactly, so a future collision with a third-party package defining the same selector is behavior-identical.

Rationale: Parley loads third-party code into images. Extension collisions are dependency hell in its most Smalltalk-shaped form; the compat layer must never cause one.

### 1.4 Namespacing & Naming

- **All Parley classes live in the `Parley` namespace.** GNU Smalltalk namespaces are suitable for organizing our own code; they are *not* an isolation mechanism (§1.2.1).
- Kernel class names are never shadowed. In particular, the contiguous version span class is **`VersionRange`**, never `Interval` (a gst kernel class).
- The string `gpm` must not appear anywhere in code, categories, docs, or artifacts. The project's only name is Parley.

### 1.5 Structural Immutability

3.2.5 has no enforced immutability, so it is achieved by shape:

- **Zero public setters** anywhere in the domain model.
- All construction flows through **class-side methods** that validate and normalize before answering an instance.
- Every algebraic or transforming operation answers a **new instance**; no domain method mutates its receiver after initialization.

The single sanctioned exception is `ManifestBuilder` (§2.1) — a deliberately mutable *edge object* outside the domain model, alive only for the duration of one `Parley define:` evaluation.

## 2. The Manifest / Metadata Trust Architecture

Authoring is programmatic; solving is static. These are different artifacts with different trust levels.

### 2.1 Authoring: `Package.st`

Developers describe their package in an executable Smalltalk file for Mix-style ergonomics. The file's outermost expression is:

```smalltalk
Parley define: [:pkg |
    pkg
        name: 'kernel-json';
        version: '0.3.1';
        dependency: 'kernel-streams' constraint: '>=1.0 <2.0' ]
```

`Parley class >> define:` creates a fresh `ManifestBuilder`, runs the block, sends `build`, and answers an immutable manifest. The builder is a **vocabulary, validator, and serialization gateway — not a security sandbox**. The file's author owns their file and machine; nothing prevents them writing arbitrary Smalltalk in it, and nothing needs to. Full builder spec: [manifest-and-serialization.md](manifest-and-serialization.md).

### 2.2 The Trust Boundary (clarified)

> **The security boundary is the static index entry, not the builder.**

At publish time, the manifest is serialized into an immutable static **index entry** in the literal micro-format. The registry serves index entries, not manifests.

**Absolute Trust Invariant:** Parley's resolver — and every consumer of *third-party* package information — operates **exclusively on static index entries**. Third-party `Package.st` files are NEVER executed, compiled, or evaluated. Evaluating a `Package.st` is something only its own author's tooling does, on their own machine, at authoring/publish time.

**Compiler Ban:** No third-party content is ever passed to `Behavior>>evaluate:`, `Compiler`, `doIt`-style facilities, or any compilation pathway — *including* content that "looks like" a harmless literal array. Reading a static artifact by compiling it is a trust-boundary violation even when the content is expected to be literals. All static artifacts are read exclusively by the literal reader (§2.4).

### 2.3 Metadata vs. Archive (the Cargo split)

Index entries (name, version, constraints, checksum) are tiny and separate from `.star` archives. Resolution touches only index metadata; archives are fetched **after** a successful resolution, at install time, and verified by content hash.

### 2.4 The Literal Micro-Format

All static artifacts — index entries and lockfiles — are a single Smalltalk **literal array** in canonical form.

**The reader** is a purpose-built recursive-descent parser (target: ~50 lines) that accepts *only*: literal arrays `#( … )`, strings `'…'` (with `''` escaping), symbols (`#name` and `#'quoted'`), and non-negative integers, plus whitespace. **Everything else is rejected** — identifiers, floats, scaled decimals, characters, byte arrays, `true`/`false`/`nil`, comments, brace arrays, and any message-send syntax. Rejection is a parse error naming the offending token and position. The reader never delegates to the compiler (§2.2).

**Canonical rendering rules** (byte-stability — required for meaningful content hashes, diffs, and the byte-identical-lockfile test):

1. Every artifact opens with a **format tag and version**: `#'parley-index' 1` or `#'parley-lock' 1`.
2. **Fixed key order** — keys appear in the schema-defined order, always all present (empty string / empty array when unset).
3. **Dependencies sorted by package name.** (Contrast: `fileIns:` order is semantic load order and is preserved exactly — see [manifest-and-serialization.md](manifest-and-serialization.md) §"Two ordering rules".)
4. Constraints are rendered via `VersionConstraint printString` — **the canonical normal form is the wire form**. Authoring sugar (`^0.4.2`) may serialize as its expansion (`>=0.4.2 <0.5.0`); this is correct. Sugar belongs at authoring time; normal form belongs at rest.
5. Deterministic whitespace: single spaces, no trailing whitespace, single trailing newline.

Schemas, writer/reader pairing, and the round-trip law: [manifest-and-serialization.md](manifest-and-serialization.md).

## 3. Phase 1 — The Algebraic Domain Model

Full specification: **[domain-model.md](domain-model.md)**. System-level summary and invariants:

- **`Version`** — immutable `major.minor.patch` value object. MVP **rejects prerelease/build tags** with a clear error (prerelease ordering is deferred whole, not half-built; `Version` comparison is the single change site if revisited). `=` and `hash` are always implemented together.
- **`VersionRange`** — one contiguous span: `min`, `max`, `includeMin`, `includeMax`; `nil` bound = unbounded. Explicit open/closed bounds (half-open ranges cannot be faked with version arithmetic).
- **`VersionConstraint` (the Keystone)** — NOT a subclass hierarchy (`Exact`/`Range`/`Union` subclasses create an N×N double-dispatch matrix and undecidable equality) and not an interval tree. A **two-level normal form**:

  > **Invariant:** a `VersionConstraint` holds a sorted `Array` of disjoint, non-adjacent `VersionRange`s. All construction passes through normalization. Two constraints denoting the same version set are structurally identical.

  Closed set-algebra protocol: `allows:`, `intersect:`, `union:`, `complement`, and derived `difference:` / `isSubsetOf:`, plus `isEmpty` / `isAny`. `complement` exists from day one because PubGrub's negative terms are complements.
- **Caret semantics — Cargo-exact:** `^1.2.3` → `[1.2.3, 2.0.0)`; `^0.2.3` → `[0.2.3, 0.3.0)`; `^0.0.3` → `[0.0.3, 0.0.4)`.
- **`Term`** — `(package, VersionConstraint, isPositive)`; negation is constraint complement.
- **`Incompatibility`** — a set of Terms that cannot all hold, plus a `cause`: **external** (`#dependency`, `#noVersions`) or **derived** (cause links to parent incompatibilities). Derived incompatibilities form a **derivation tree**; **`ConflictReport`** wraps the root and renders narrated proofs via `printOn:`.
- **`LibraryManifest`** (loose constraints) vs. **`ApplicationManifest`** (environment + lockfile): the Bundler Gemfile/gemspec lesson, preventing libraries from shipping pins that deadlock the graph.

## 4. Phase 2 — The Pure Resolution Engine

Full specification: **[resolver.md](resolver.md)**. System-level summary and invariants:

- **`PackageSource` protocol** (Cargo's `Source` model): `DirectorySource`, `GitIndexSource`, `RegistrySource` all answer `versionsOf:`, `manifestFor:version:`, `fetch:version:`. The resolver never knows where packages live.
- **Purity contract:** `Resolver` is a pure function of (root manifest, immutable index snapshot). Zero live I/O mid-resolution. Resolution answers exactly one of two **values** — a `Resolution` or a `ConflictReport` — never hot-loop exceptions.
- **Strategy seam:** `Resolver strategy: BacktrackingStrategy new` (MVP) → `PubGrubStrategy new` later, without touching the domain model. The MVP's `Term`/`Incompatibility` objects are PubGrub's clauses; only the loop around them changes.
- **`ConstraintLedger` — never intersect anonymously.** The running constraint on a package is never stored bare; the ledger keeps the intersection *and* the contributing `Term`s. When an intersection collapses, the `Incompatibility` constructs itself from provenance the ledger already holds. **The search loop contains zero explanation-flavored branches.**
- **`BacktrackingStrategy`:** deterministic DFS. **Smallest-domain-first** package selection (fewest allowed candidates, ties alphabetical), candidates highest-first. **Copy-on-descend** ledgers — backtracking discards a ledger; there are no undo logs. Conflicts are created at collapse points on the way down and merged at exhaustion points; the unwind carries finished values. **No backjumping in the MVP** (the provenance data already supports it; the payoff belongs to `PubGrubStrategy`).
- **Lockfiles, day one:** literal micro-format, exact versions + archive content hashes. Fast path: verify pins; re-resolve only on manifest change or explicit `parley update`. Applications commit lockfiles; libraries do not ship them as constraints.

## 5. Phase 3 — The Orchestration Bridge

- **`Installer`** — strictly post-resolution: fetch each `.star` archive via its `PackageSource`, verify by **content hash** (content-addressed cache; integrity for free), register via the flagless `gst-package` baseline (staged under the star's true name — Doc D §4) and local `PackageLoader`. The installed set is an immutable value; switching or rolling back an environment re-points rather than mutates.
- **`ExecutionScope`** — the honest `bundle exec` for 3.2.5. Holds the resolved, content-hashed `.star` set; answers `run:` by composing and launching a **clean child `gst` invocation** with a curated package path, so only the exact resolved set is visible to that image's `PackageLoader`. The scope is a domain object: inspectable, composable, and the single home of invocation logic.
- **`CLI` / `CliResult`** — the six verbs as an orchestration that answers a **value**: the CLI never prints and never terminates the image.

## 5.5 Phase 4 — The Ecosystem (Sprint 7+)

- **`Publisher`** — manifest → toolchain-built `.star` → populated index entry, landed into a destination index. Refusal-first (releases are immutable), batched pre-flight, destination-confined staging, build fail-stop. Parley never zips: the toolchain owns the archive format (Doc F §1).
- **`GitIndexSource`** — a git checkout used as an index directory, by pure composition over `DirectorySource` plus exactly one git moment at `snapshot`. `fetch:version:` runs no git, so install-time bytes are the ones resolution saw (Doc F §3).
- **`CommandLine` and the diagnosis boundary** — the composition root of one invocation: the flag grammar, the wiring (all state derived from the *working directory*, never the process cwd), and the error boundary. **No Parley command ever answers a backtrace, and no failing command ever exits `0`.** A declared Parley error is a diagnosis at exit `1`; anything else is a defect in Parley at exit `70`, distinct so a script can tell "your input is wrong" from "the tool is broken". The boundary is a **closed set with a law**, and the shipped binary is law-guarded — glue that chooses an exit code is not glue, it is the product (Doc E §4.2/§4.3, §8 decision 30).

## 6. Axiomatic SUnit Testing

The algebra is tested **as laws** over randomized generated versions and constraints (hundreds of generated cases per run, **deterministic seed** for reproducibility):

1. Commutativity and associativity of `union:` and `intersect:`.
2. De Morgan: `(a union: b) complement = (a complement intersect: b complement)`, and the dual.
3. Double complement: `a complement complement = a`.
4. Absorption: `a union: (a intersect: b) = a`.
5. Identity/annihilator: `a intersect: VersionConstraint any = a`; `a intersect: VersionConstraint none = VersionConstraint none`.
6. **Normalization invariant:** after any construction or operation, ranges are sorted, disjoint, non-adjacent.
7. **Membership consistency (randomized):** for random `v`: `(a intersect: b) allows: v` ⇔ `(a allows: v) and: [b allows: v]` — the primary net for bound-inclusivity off-by-ones.
8. **Round-trip identity:** *build → serialize → read = build* — the writer/reader pair composes to the identity on manifests, proving the authoring path and resolver path converge on identical values.
9. **Literal-reader rejection:** any non-literal input MUST fail to parse with a positioned error.
10. Resolver purity and determinism: same manifest + same snapshot ⇒ identical `Resolution` and **byte-identical lockfile**.
11. Conflict-report snapshots: derivation trees render stably; tests send messages directly to failed `ConflictReport` trees.

## 8. Decision Log

> **This is the single canonical decision log.** It is referenced from every other design doc as "§8 decision N" and from `.github/copilot-instructions.md` §2. It was previously a one-line summary of a fuller log kept in the operator's local master plan, and the two drifted — decisions 34–37 existed only in the untracked copy while tracked docs already cited 35 and 37. Mirrors drift; this repo retired its `design-*.md` mirrors for the same reason. **There is now one copy, and it is this one.** Adding a decision means adding it here, in the same commit as the doc change that cites it.


1. **Target 3.2.5; extensions only in `*parley-compat`** — modernity modeled into the image, collisions contained.
2. **Manifest/metadata split** — Mix ergonomics at authoring, Cargo static determinism at solving.
3. **Static index entry = the security boundary; builder = ergonomics/validation** — no evaluation sandbox is built because none is needed.
4. **Compiler ban for third-party content** — the trust invariant holds at every layer, including "harmless-looking" literals.
5. **Literal micro-format + literals-only reader** — STON absent in 3.2.5; self-contained scoping forbids porting one.
6. **Canonical byte-stable serialization** — hashes, diffs, and lockfile determinism require it.
7. **Two-level constraint normal form** — decidable equality, no N×N dispatch, canonical printing for free.
8. **Cargo-exact caret; no prereleases (MVP)** — smallest well-defined semver surface.
9. **`complement` from day one** — the keystone must already speak negation for PubGrub.
10. **Never intersect anonymously** — provenance recorded on the way down; explanations emerge from data.
11. **Values, not exceptions, from resolution** — purity, testability, no hot-loop ceremony.
12. **Copy-on-descend backtracking** — immutable values make backtracking "return from the method".
13. **Smallest-domain-first** — deterministic, fail-fast, legible derivation trees.
14. **No backjumping in MVP** — data supports it; payoff belongs to `PubGrubStrategy`.
15. **Lockfile day one** — determinism as a product feature.
16. **Process-level sandboxing** — 3.2.5 cannot isolate versions in-image; child `gst` with curated paths is the honest `bundle exec`.
17. **Explicit DSL methods; DNU as error path only** — the manifest vocabulary is browsable API surface (senders, implementors, completion, hover docs); `doesNotUnderstand:` turns typos into rich `ManifestVocabularyError`s.
18. **Axiomatic SUnit laws** — set theory proven over generated versions.
19. **`Parley.Parley` entry-point gateway** — 3.2.5 namespaces swallow unknown keyword sends as binding setters; a shadow class inside the namespace preserves the Doc B §2 syntax verbatim without any kernel extension. Bare top-level `gst Package.st` is deferred to the Phase 3 tooling. (Sprint 1, issue #3.)
20. **Single-line canonical rendering** — §2.4 rule 5's "single spaces between elements" admits no newlines inside an artifact; multi-line listings in the specs are illustrative pretty-printing. The canonical byte form is one flat line plus a single trailing newline. (Sprint 1.)
21. **`Term` carries an equality-excluded `origin`** — provenance (the `Incompatibility` that imposed the term) rides the term itself, so derived incompatibilities recover their parent causes from `conflictFrom: acc terms` alone; `=`/`hash`/`negated` ride the three value fields only. (Sprint 2, issue #4.)
22. **Decision pins** — decisions are recorded in the descent ledger as positive exact-pin terms; late-edge-vs-decision conflicts surface through the existing collapse machinery with full provenance, keeping the search loop free of soundness re-check branches. (Ruled at the Sprint 2 close-out on issue #4; implemented in Sprint 3, issue #5 — the "no code outside tests consumes a `Resolution`" constraint is lifted.)
23. **`ApplicationManifest` carries no value equality (`=`/`hash`)** — it is a plain association value; adding equality would force `=`/`hash` onto the settled `LibraryManifest` (identity-equal by design). Any sprint that needs manifest value equality must declare `LibraryManifest` in scope explicitly. (Ruled at the Sprint 3 RED review on issue #5.)
24. **Source-protocol unknowns are ordinary values, never errors** — `versionsOf:` answers an empty collection and `manifestFor:version:` answers `nil` for an unknown (package, version); scan *problems* batch into one `SourceError` (`problems` strings in sorted-filename order, `ManifestError` house style); an empty-but-clean directory is an empty snapshot and resolution fails as an ordinary `#noVersions` value. Every future source (`GitIndexSource`, `RegistrySource`) follows this contract. (Pinned at the Sprint 4 RED review on issue #6.)
25. **The install-pipeline contract** — per triple in sorted package-name order: an empty `sha256` is a problem before anything else (`''` is never a store key), then cache-hit (a contained hash skips fetch entirely), then fetch, then verify-then-store (a mismatch never enters the store). Only a `SourceError` from `fetch:version:` becomes a batched `InstallError` problem — any other error propagates (a non-conforming source is a defect, not an install problem). The registration plan lives on `InstalledSet` (`registrationCommandsFor:`) as pure string values; `InstalledSet` carries no value equality (decision-23 precedent); `ContentStore` roots are created lazily, one directory level deep. (Pinned at the Sprint 5 RED review on issue #7.)
26. **Name-equality MVP constraint + staged registration plan** — a Parley package's entry name IS its star's internal `package.xml` name (lowercase per Doc B §3.4; the toolchain's name check is pure string equality and accepts lowercase). Forced by 3.2.5: `Kernel.StarPackage` rejects any star whose filename differs from its internal name, binding both `gst-package` and the child's `PackageLoader` — so registration stages each content-addressed archive under its true name inside the target (`install -D -m 644 <store path> <target>/.parley-staging/<name>.star`) then registers it with the **flagless** `gst-package --target-directory` (3.2.5 has no `--install` option despite its help text). The plan stays a pure value on `InstalledSet`, now two pair-adjacent lines per package; archives stay opaque — the true name comes from the tuple, never from reading the archive. Carrying a divergent archive filename through metadata was considered and rejected (it forces a lockfile schema bump or a new `PackageSource` protocol method). (Ruled mid-Sprint 6 on issue #8.)
27. **`RegistrySource` is deferred entirely, not stubbed** — registry hosting is deferred, and a registry source without a registry is either a renamed `DirectorySource` or an untestable HTTP shell; both teach nothing and leave a misleading name in the inventory. The `PackageSource` protocol already proves its polymorphism with two real implementations (`DirectorySource`, `GitIndexSource`); `RegistrySource` arrives with hosting. (Ruled by the operator at Sprint 7 staging.)
28. **A declared settled-class exception is a *public contract* exception, not a line-count exception** — Sprint 7 declared that `IndexEntryWriter` "gains exactly one selector." Keeping `write:on:` byte-identical alongside the new `write:archive:sha256:on:` was done by extracting their shared rendering into a private `writeHeadOf:on:`, so the two forms cannot drift. That private extraction is *inside* the declared exception: same class, same change, no new public contract, and the alternative — duplicating the canonical renderer — is precisely the drift the S5 regression guard exists to catch. Private helpers in service of a declared change need no separate declaration; new public selectors always do. (Ruled by the operator at the Sprint 7 close-out on issue #9.)
29. **Fail-stop governs the run that failed, not the run after it** — `Publisher` staging sweeps a `.parley-publish-stage/` left behind by an earlier failed build before recreating it. "Fail-stop never cleans up behind an error" preserves the *failing* run's evidence for inspection; it does not make the next invocation non-deterministic or un-re-runnable. Doc F §1 step 3 states the sweep. (Ruled by the operator at the Sprint 7 close-out on issue #9.)
30. **Glue that chooses an exit code is not glue** — Doc E §4.2 declared `bin/parley-main.st` "glue, not logic — excluded from SUnit obligations." That exemption let the hardcoded file-in list miss `src/publish/`, so the shipped `publish` verb answered a `doesNotUnderstand:` backtrace and **exited `0`** — fail-wrong, the one failure mode the architecture exists to prevent, undetectable by 409 laws. The exemption is withdrawn: the wiring, the flag grammar and the error boundary move into `Parley.CommandLine` (a composition root, not a manager) with laws; `bin/` keeps only file-in, one send, print and quit, and is itself law-guarded by a drift test requiring it to name every `src/` subdirectory. An escaping error becomes one diagnosis line and exit `70` (`EX_SOFTWARE`), distinct from the `1` of a diagnosed problem, and never a backtrace. (Ruled by the operator at Sprint 8 staging, from a defect found at the Sprint 7 close-out.)
31. **A boundary must blame the right party, so `ManifestFile` checks the path** — Sprint 8's third declared settled-class exception, granted at the RED review. 3.2.5's `FileStream fileIn:` signals a kernel `SystemExceptions.FileError` on a missing file, so `ManifestFile load:` never reached its define-less check and `resolve` before `parley init` — the most ordinary user error in the tool — arrived at the §4.2 boundary *undiagnosed* and would have been answered with exit `70`: "this is a defect in Parley, not in your project." Exit `70` on that input is fail-wrong in its second form: not a lying exit code, but a lying attribution of blame, and a boundary whose flagship case is misfiled is not a boundary. `load:` now checks the path first and signals one pinned `ManifestError`, so issue #10's S4 is exit `1` as specified. The alternative — restating S4 as exit-`70` — was considered and rejected: it would have made the sprint's own motivating example a permanent exception to its own rule. (Ruled by the operator at the Sprint 8 RED review on issue #10.)
32. **The closed-set law states what the code can support: "declared undiagnosed with its ground named", not "provably never signaled out of a verb"** — Doc E §4.2's original wording was false for three of the five undiagnosed classes: `IndexEntryParseError`/`IndexEntryFormatError` escape the `CLI`'s `parley.lock` read and `ManifestVocabularyError` escapes `ManifestFile load:` on an authoring typo. Rather than let a law assert something untrue — the failure mode this whole sprint exists to end — the second bucket is renamed and each escape path is declared by name in `CommandLineFixtures>>undiagnosedErrorClassNames`. The law's guarantee is undiminished: the two lists must **partition** the enumeration, so no new error class can drift into the `70` bucket without someone deciding it should. All three escapes land nonzero, one line, no backtrace, so fail-stop holds; what they lack is the right blame. **Ruled gap carried out of Sprint 8:** reclassifying them as exit-`1` diagnoses needs a lock-validation boundary and an authoring-error boundary — design, not a fix — and is scheduled for Sprint 9. (Ruled by the operator at the Sprint 8 RED review on issue #10.)
33. **A reviewer amendment is delivered work and carries the same burden of proof** — at the Sprint 8 RED review the operator verified every pinned wording byte-for-byte against the settled source, amended three files, and never cross-checked that the fixture *feeding* S2 paired with the oracle S2 asserted against: `SourceFixtures populateDiamondIn:` writes placeholder shas while `ExecFixtures diamondLockString` embeds the true digests, so the two literals could never be equal and no correct `CommandLine` could have satisfied the assertion. The agent found it in GREEN, checked it by hand through the shipped binary rather than asserting it, and **halted instead of patching a signed-off test** — the right call, and the rule stands: amendments to reviewed tests are the operator's. 40. **`why` and `tree` walk the pinned graph, not the resolution ledger** — the roadmap described these verbs as "near-free from the `ConstraintLedger`'s provenance". 42. **A digest that cannot be a digest is a shape error, not a tampering report** — the lock's `#sha256` and the entry's `#archive` digest are validated as *strings* and never as hex. A typo'd digest therefore passes both boundaries and fails later at `ContentStore>>verifyHash:`, which reports **corruption** — "the store never repairs itself; this is detection" — when the truth is a mistyped character in a hand-edited file. Nonzero and no backtrace, so not fail-wrong in the exit-code sense, but the same *blame* misattribution as decisions 31 and 35: the operator is told their cache is compromised when their lockfile has a typo. Both boundaries now require 64 lowercase hex characters, through the one `SchemaShape isHexDigest:`. Validating the shape does **not** validate the truth — `verifyHash:` remains the only thing that says a digest matches its bytes, and it keeps its corruption wording for the case that really is corruption. **The empty string is exempt on the lock side**, added at the Sprint 11 RED review: `''` is what the settled writer renders for a pin whose entry declares `#archive #()`, so a boundary that rejected it would reject Parley's own output and would shadow the settled `Installer` "no published archive" diagnosis with a lockfile repair instruction the operator cannot act on. The exemption is for absence, not for laxity — every non-empty digest is held to the full 64-hex shape. The entry side needs no exemption: absence there is `#archive #()`, which carries no digest string at all. 43. **When a toolchain offers no reflective mechanism, harden the textual one and bound the claim honestly** — the deserialization-boundary drift law searches source text because 3.2.5 offers nothing better (§8 decision 38, corrected). Hardening means normalizing whitespace so a receiver and selector split across lines are still one send, which closes the accidental miss. The *deliberate* miss — a send reached through a temporary, `reader := IndexEntryReader. reader readFrom: …` — cannot be closed textually and has no reflective fallback here, so it is answered by a **convention with a law**: every sender spells its receiver, and the enumeration's pinned answer is what detects a violation the moment one appears. 44. **A report on one file names its first defect; a report on a project names them all** — `check` answers every problem it finds (the `PinVerification` problems, then one line per retired pin in pinned-name order), while the lock read answers only its first. Read side by side these look like two answers to one question, and the roadmap carries "the lock check batches nothing" as a standing gap, so the difference is worth stating rather than leaving to be rediscovered as an inconsistency. They are answers to *different* questions. The lock boundary reports on a single file the operator is about to repair by hand, where the repair is the same whichever defect is named first and a list of five would be five trips to the same line. `check` reports on the **state of a project**, and its one job is to be run in CI: a first-problem-only verdict turns one red build into three, each revealing the next problem, which is the shape of tooling people learn to stop trusting. The rule that falls out: **batch when the reader will act on all of it at once, name the first defect when they will act on one thing at a time.** (Ruled by the operator at the Sprint 11 close-out on issue #13.)
45. **`parley exec` cannot promise a script's success on 3.2.5, so it promises what it can and says so** — the highest-ranked open item since Sprint 8 was that `parley exec broken.st` prints the child's backtrace and exits `0`: 3.2.5 continues past an unhandled error at the top level of a filed-in script, so the child really does exit `0` and Parley really does report it faithfully. What remains is capturing the child's output and pattern-matching a backtrace, which is heuristic, and which would end the live streaming that makes `exec` usable. The ruling: **`exec` stays a faithful pass-through of the child's exit code**, and the guarded-script idiom — a script whose success matters ends with an explicit `ObjectMemory quit:` — is the documented answer, already carried in the README as a consumer constraint. 46. **A selective update is a normal resolution of a smaller world** — `parley update <pkg>` must move one package and hold the rest, and the obvious implementation is to teach the resolver about held packages. That is the mistake decision 37 already refused once. Holding lives in the **snapshot**: `IndexSnapshot>>holding:` answers a new snapshot offering exactly the held version for every held name, and `Resolver`, `BacktrackingStrategy` and `ConstraintLedger` are neither modified nor entered differently — a future `PubGrubStrategy` inherits selective update for free, exactly as it inherits retirement. Two consequences follow and both are ruled here. **A held pin outranks a retirement:** `versionsOf:`'s retirement filter answers "what may a *fresh* resolution pick", and a held pin is not being picked but kept — the second half of decision 37 applied one layer up, so an unrelated retirement can never fail a selective update, and `check` remains the verb that reports retirement as a problem. **Provenance stays at the CLI:** when holding the rest makes the named package unmovable, the resolver answers a truthful `ConflictReport` about a world with few candidates but cannot know why the world was small, so the verb prepends the sentence naming what was held — blame at the boundary that had the context, the placement decisions 31, 35, 42 and 44 each arrived at independently. (Ruled by the operator at Sprint 12 staging on issue #14.)
47. **Narrowing can only offer what the snapshot can describe** — decision 46 says `holding:` offers exactly the held version for every held name, and read literally that also covers a version the index no longer publishes at all: the state an index owner leaves behind by *deleting* an old entry, which Sprint 12's own S8 fixture is built on. Offering it would be a soundness defect rather than a courtesy. `sha256For:` answers `''` and `dependenciesOf:` answers `#()` for a release the snapshot never saw, so a selective update holding one would write a lock tuple with an **empty digest** — a file the Sprint 11 lock boundary rejects, meaning `update` would have quietly manufactured the corruption `check` exists to catch. The rule: **narrowing offers the held version only when the snapshot holds a record for it, and nothing for that name otherwise.** This is not a retreat from held-beats-retired, and one property separates the two cases — a *retired* release is still fully described (§2.1 keeps the describing accessors answering), so it can be kept; a *deleted* one is not described at all, so it cannot. Held-beats-retired governs what may be **picked**; describability governs what can be **written down**. The consequence a deleted held pin produces is an ordinary unsatisfiable narrowed world (the held-pins line plus a `ConflictReport`, exit `1`, no lock written) — sound, but reading as a version conflict when the real defect is a missing index entry. Diagnosing it precisely is a **carried gap, unscheduled**. (Ruled by the operator at the Sprint 12 red review on issue #14; Doc C §2.2.)
48. **Already-newest changes what a verb reports, never what it does** — Sprint 12's `update <pkg>` answers a pinned success line when the named package is already at the newest version its constraints allow, and the sprint's tests pin the line, the exit code and the byte-identical lock rewrite while deliberately leaving the *pipeline* unconstrained. That freedom was flagged at the close-out rather than left to drift, because an unconstrained behavior inside a settled verb is exactly what a later refactor changes silently. The ruling: **install and register run unconditionally.** The pins being unchanged says nothing about whether the store and target directory still hold them — a cleared store, a fresh checkout or a machine that never installed this project are all ordinary, and a verb that skipped the pipeline would answer exit `0` while registering nothing, which is the "reads as a verb that did nothing" failure one layer down from the one the pinned line exists to prevent. `Installer install:` is idempotent and cache hits skip fetch, so the unconditional run costs one cache-hit pass. The same reasoning governs any future verb tempted to short-circuit on "nothing changed": the report may narrow, the contract may not. (Ruled by the operator at the Sprint 12 close-out on issue #14; Doc E §4.1.)
49. **Parley never re-renders a file it did not write** — `parley add` must change `Package.st`, and the choice sat unresolved long enough to gate a sprint: a formatting-preserving text edit, or a `ManifestBuilder` round-trip that rebuilds the file from the loaded manifest. The round-trip is the easy build and is **disqualified**, not merely disfavored. `Package.st` is executable Smalltalk the author owns (§2.1, §2.2); the manifest is a lossy *projection* of it, carrying none of the author's comments, formatting, reasons, or any Smalltalk that is not vocabulary. Re-rendering would silently substitute a different program that happens to build an equal manifest, and would damage the most careful authors worst. It would also invert this project's central boundary: canonical byte-stable rendering is a law for index entries and lockfiles **because Parley owns those artifacts** (Doc B §5.4), and `Package.st` is on the far side of that line. The mechanism is therefore **recognize or refuse**: insert one `dependency:constraint:` clause into a recognized `Parley define:` cascade preserving every other byte, and when the shape is not recognized change nothing and answer the exact text to paste. Three consequences are ruled with it. **The edit is verified semantically** — re-load through the settled `ManifestFile load:` and assert the manifest gained exactly the new dependency, because Parley already owns the authority on what a `Package.st` means and a textual edit that is not checked by it is a hope. **The verb is atomic** — manifest, lock, store and registration all move or none do, and any refusal restores the original bytes; the alternative is a manifest naming a dependency the lock does not pin, which is the exact state `PinVerification` exists to call broken and which the tool would have manufactured. **Adding holds the existing pins** — the third application of decision 37's trick after retirement and selective `update`, for decision 46's reason: adding one dependency is not a license to move the others. (Ruled by the operator at Sprint 13 staging on issue #15; Doc B §2.1, Doc E §4.1.) **Narrowed at the Sprint 13 close-out: atomicity is the manifest and the lock, not the store.** As first written, "manifest, lock, store and registration all move or none do" claimed more than the code does or should: the shipped rollback restores the manifest and the lock, and a fetched archive may remain in the content-addressed store. That is the right line rather than an unfinished one. The state atomicity exists to prevent is a manifest naming a dependency the lock does not pin — the one `PinVerification` calls broken — and only that *pair* can manufacture it; a hash-verified archive is inert until a lock pins it, is re-used rather than re-fetched, and is reported by no verb, so it is not observable project state. Scheduling store rollback would add machinery to erase something inert that another pin may legitimately share. The narrower sentence is now in Doc B §2.1 and Doc E §4.1, and it reopens if the store ever becomes observable as state (pruning, a size budget, or a verb reporting contents). The same shape as decisions 43 and 45: a claim that cannot be made should be narrowed in writing, not faked. (Ruled by the operator at the Sprint 13 close-out on issue #15.)
50. **The one I/O moment may be a closure, never a callback** — the sparse-index client's roadmap description, "per-package metadata fetched on demand", read literally contradicts the purity contract: Doc C §2 makes `snapshot` the source's one I/O moment answering a fully materialized immutable value, and AGENTS.md §6 bans live I/O mid-resolution. A sparse index cannot enumerate its packages, and the set of names that matter is only discoverable by walking the dependency graph — which is resolution. The disqualified build is the obvious one: teach `IndexSnapshot` to fetch lazily, which would reopen `setReleases:`, the purity contract, the determinism laws, and every strategy built on them, for exactly the reason in-resolver holding was refused twice (decisions 37 and 46). The ruling: **`SparseIndexSource snapshot` performs a transitive pre-fetch closure** — seed with the root manifest's declared names union the lock's pinned names when a lock exists, fetch each reachable package's version listing, fetch every entry the listing names, read the names those entries declare, and repeat to fixpoint — then build one complete `IndexSnapshot` over the reachable closure and answer it before resolution begins. The one I/O moment becomes a loop instead of a directory scan; the resolver, `IndexSnapshot` and both strategies are untouched, the fourth consecutive application of the put-it-in-the-source pattern. Two consequences are ruled with it. **An unreachable name is an undescribed name:** a package the closure never fetched is indistinguishable from one the index does not publish, which is already a ruled state — decision 47's describability line governs it unchanged, and a listing miss for a declared name is therefore an ordinary empty candidate set, never an error. **"Fetched on demand" is narrowed in writing:** the roadmap's phrase now means "on demand of the closure walk, before resolution begins" — the wire efficiency the sparse shape exists for (fetch only the reachable packages, not the whole index) is preserved in full; what is refused is only the callback timing. **Two settled-class exceptions are declared with this ruling:** `CommandLine` (the `--index` row of `sourceFlags`, the fourth row of `deserializationBoundaries`, the usage lines — its first) and `IndexEntryReader` (`formatTags` grows by `#'parley-listing'`, Doc B §7's declared-never-silent rule; the rejection sentence grows in the same change by construction, since `formatTagsText` renders it from the whitelist). (Ruled by the operator at Sprint 14 staging; Doc F §7, Doc B §5.6, Doc C §2.)
51. **A sparse source is told what matters; it never reads the project to find out** — decision 50 rules that `SparseIndexSource snapshot` seeds its closure with "the root manifest's declared names union the lock's pinned names" and named no mechanism for obtaining them. The Sprint 14 RED agent halted on exactly that omission (issue #16) and offered three builds; all three are disqualified by one rule, which is the ruling's whole weight: **the source must never read `Package.st` or `parley.lock`.** Both are operator-editable files whose deserialization boundaries are already owned — `ManifestFile` by file-in, `CLI` by the §4.1 lock read — so a second reader would duplicate a row of `CommandLine class >> deserializationBoundaries` and invent a second wording for the same malformed file, the defect class decision 35 exists to prevent. A `PackageSource` whose `snapshot` can signal `ManifestError` or `LockError` contradicts Doc C §1, which already forbids the adjacent thing in writing (`manifestFor:version:` is "NEVER a `Package.st` evaluation"). And deriving a working directory from the cache path would bake the *flag's* layout convention into a class Doc F §7.5 requires to be directly constructible under `tmp/`. **The ruling: the seeds are values, supplied by the caller, through one new message on the `PackageSource` protocol** — `seededWith: someNames` answers a source; `SparseIndexSource` answers a copy holding the seeds, and the two scanning sources answer `self`, because a source that reads its whole index needs no hint. The constructor is **untouched**: `base:cache:runner:`, exactly as Doc F §7.3 always spelled it. What was missing was protocol, not a keyword — which is why every candidate that grew the constructor felt wrong to the agent that proposed them. The caller is the **`CLI`**: the only object holding both the loaded manifest and the read lock at the moment `snapshot` is sent, so seeding there duplicates no boundary and needs no new collaborator. Polymorphism, never a kind-check — `respondsTo:` is a kind-check spelled differently — and the resolver still never learns which source fed it. **One consequence is ruled with it: `add` seeds the name it is adding.** `CLI >> add:constraint:` takes its snapshot *before* it edits `Package.st`, then resolves the post-edit manifest against it. That is invisible to a scanning source, which holds the whole index anyway, and fatal to a sparse one: the added name is in neither the manifest nor the lock, so the closure never fetches its listing and decision 47 turns the miss into an ordinary `#noVersions` conflict. `parley add <name> <constraint> --index <base>` would have failed **always**, with a plausible and wrong diagnosis, and no Sprint 14 scenario as staged could have seen it. **Three further settled-class exceptions are declared with this ruling:** `CLI` (a private seed set, the six `source snapshot` sites, and `add`'s extra name), `DirectorySource` and `GitIndexSource` (`seededWith:` answering `self`). There is no `PackageSource` superclass to carry a default, and inventing one to save two two-line methods would be the larger change. (Ruled by the operator at Sprint 14 RED on issue #16; Doc C §1.2, Doc F §7.3/§7.5, Doc E §4.1.)
52. **A best-effort read may swallow only the errors whose diagnosis it defers to** — `CLI >> seedNames` gathers the decision-51 seed set from `Package.st` and `parley.lock`, and it must not pre-empt those files' settled diagnoses: `resolve` ignores a corrupt lock and stays exit `0` (Doc E §4.1), and the missing-manifest sentence belongs to `ManifestFile` (decision 31). Both catches are therefore right in *intent* and too wide in *extent*. As shipped they catch `Error`, which also swallows a programming error — an MNU from some later rename of `dependencies` or `packageNames`, say — and what a swallowed error leaves behind is not an exception but a **silently empty or partial seed set**. Under a scanning source that is invisible, because `seededWith:` answers `self` and the whole index is read anyway. Under `--index` it is decision 47's describability line: the closure never fetches the missing names, and the verb answers a `#noVersions` `ConflictReport` at exit `1` **blaming the package**. That is precisely the wrong-blame diagnosis S16 was written to prevent, resurrected as a silent one that no law can see — every law's seed gathering succeeds, so the failing path is the one no fixture exercises. 54. **The prebuilt image is deferred on its measurements, and the blocker is staleness rather than speed** — the roadmap carried "the prebuilt-image decision **taken on measurements** rather than intuition" as part of release hardening, and Sprint 15 took them (`sprint-15-notes.md`, 20 runs each): bare `gst` 12.3 ms, the current file-in path 55.5 ms, a 3.2 MB prebuilt image **5.6 ms** — faster than bare `gst`, because loading a snapshot skips kernel bootstrap. So file-in costs ≈43 ms and an image saves ≈50 ms per invocation. **Ruled: defer, with named triggers — not refuse, and not build.** The saving is real but not user-visible for a tool whose ordinary verbs spawn `gst-package`, `git` or `curl`: it is 63% of a metadata-only `resolve` against a local directory, 22% of a `publish`, and less of `install` or `exec`. What decides it is not the 50 ms but what the artifact costs to hold: a 3.2 MB build product that must be kept in step with `src/` and that **goes stale silently** — an image built from older sources runs older code and says nothing, which is the fail-wrong class this project refuses everywhere (decisions 31, 35, 42, 44), and no law today could catch it. Shipping the artifact therefore means shipping a freshness guard with it, and that is design rather than tooling polish. 56. **A boundary validates that its file is readable before it validates what the file says** — every file boundary in Parley checks *shape*: is this a `#'parley-lock' 1` artifact, does this entry parse, is this digest 64 hex characters. The readability defect names the two-step repair that works, ending in the settled *missing*-lock repair: once the path is removed the lock is **missing**, not corrupt, and `resolve` is the verb that writes a first one. The settled corrupt-lock behaviour is the line that separates the cases: a lock that is *readable but malformed* is still ignored by `resolve` at exit `0`, because `resolve` is about to overwrite it, while a lock that cannot be read as a file is refused by **every** verb including `resolve`, because the write that would repair it cannot succeed either. **The `exec` script** (Doc E §4.1) is checked before any process is spawned, answering one line naming it at exit `1`. 57. **Asking a tool a question is not an error** — `parley --version` answered one line at exit `0` (decision 53's sprint), while `parley --help`, `parley -h` and `parley help` printed the usage text and exited **`2`**. Same product, same kind of question, two different answers, and the one that fails is the first command a new user types — enough to fail any `set -e` script or CI smoke check that asks a tool to describe itself. The ruling: **`--help` joins `--version` as a declared question flag** — recognized once, ahead of verb dispatch and before `createStateDirectories`, answering the pinned usage lines at exit `0`; `-h` and the bare verb `help` are accepted spellings, because a user who guesses any of the three has asked the same thing. **The other half of the line is what does not move:** `parley` with no argv, an unknown verb, and a *trailing* `--help` or `--version` on a verb (`resolve --help`) all stay usage errors at exit `2` — failing to say what you want is an error even though asking for help is not. Held to one declared special case apiece, never a general "valueless flags are grammar now" change, which would silently alter what every settled trailing-flag law is testing without touching a line of them (the Sprint 15 reasoning, applied a second time to the second flag). **Second half of the ruling, found the same way and belonging to the same reason: no usage error creates project state.** `--version` was placed before `createStateDirectories` because state created by a question is state created by a question — and that reason covers every argv that never reaches a verb, which the shipped ordering did not honour. `parley`, `parley nonsense` and `parley resolve` (no source) each created `<cwd>/.parley/packages` *before* answering usage at exit `2`, so typing `parley` in any directory to see what it does left a directory behind. It was found when a bare `parley` run from the repository root during the readiness audit created `.parley/packages` there and broke two settled laws — the tool contaminating its own checkout, caught by the suite rather than by anyone noticing. A command that refuses to run leaves the filesystem as it found it, which is the rule `publish` already follows when it declines to create a destination it refuses (Doc F §1) and the rule every other refusal in Doc E follows. `createStateDirectories` therefore runs only once a verb is going to run. **Where that determination lives, ruled at the Sprint 16 RED review** on the agent's halt-and-ask: the ordering demands that `CommandLine` know whether a verb is going to run *before* it creates anything, and that knowledge — the verb list, and which verbs require a source — belongs to `CLI`. The three alternatives were each rejected on a stated ground: duplicating the grammar in `CommandLine` is exactly the drift the `sourceFlags` / `publishLayouts` / `deserializationBoundaries` tables exist to prevent; creating the directories *after* the run is impossible on this toolchain, because `ContentStore>>ensureRoot` needs `.parley` to exist and 3.2.5's `Directory create:` is not recursive (probed at RED); and creating them and deleting them on exit `2` satisfies the assertion while violating the rule the assertion is about. So **the dispatch's own "is this argv going to run a verb?" determination is extracted into one predicate on `CLI`, which `CLI>>run:` itself consumes, and `CommandLine` asks that predicate before `createStateDirectories`** — one definition, no duplicated grammar, no new class. Three constraints make it a single definition rather than a relocated one: the dispatch is *expressed in terms of* the predicate, so no verb can ever be recognized by one and not the other; the predicate is a function of argv alone and touches no filesystem, because a determination that read files would be doing the verb's work before the verb; and `cliWithSourceIn:` stays *after* `createStateDirectories`, since the `--git`/`--index` builders create `.parley/git` and `.parley/index` and need the parent. This is the fourth declared settled-class exception on `CLI` for Sprint 16. (Ruled by the operator at Sprint 16 staging on issue #18, and the determination's site at the Sprint 16 RED review; Doc E §4.2.)
58. **A remedy line is asserted only when it has been checked** — `add` and `update <pkg>` resolve against a snapshot holding the existing pins (decisions 46, 49), and when that resolution fails they print the held-pins line — *the other pins were held at their locked versions - run parley update to move everything* — above the settled `ConflictReport`. 59. **A boundary that writes a file owes the same diagnosis as one that reads it, and a general rule owes its whole domain** — decision 56 ruled that a boundary reading a file first requires a regular readable path, and Sprint 16 applied it to three boundaries. Probed at the Sprint 16 close-out, **six ordinary filesystem states still answered `internal error: … - this is a defect in Parley, not in your project` at exit `70`**, and five of them are the rule's mirror image: a read-only `parley.lock` under `resolve`; a read-only project directory under `resolve`; a read-only `Package.st` under `add`; `init` into a read-only directory; `publish` into a read-only destination; and an unreadable index entry or `.star` archive — the last of which is decision 56's own domain, unapplied, while `DirectorySource` already carries the sentence `missing or unreadable archive file`. Three of the six never name the offending path at all (`FileError: Permission denied`), which is worse than the state decision 56 was ruled to fix. **Two rules, and the second is why the first was missed.** *First:* **a boundary that writes a file requires that path to be writable before it commits to the write, and answers its own declared error naming the path and a remedy when it is not** — a read-only checkout, a root-owned file and a `chmod -R a-w` cache are operator states, not Parley defects, and exit `70`'s sentence is a false attribution of blame in every one of them. *Second, and portable:* **a rule stated generally is owed its whole domain before the sprint that states it closes** — the unfixed instances are already defects rather than future risk, and the domain includes the rule's mirror. Sprint 16's close-out ranked the remaining exposure prospectively (*"the next file boundary added will be in the same blind spot"*), which is a claim that the present is safe; six `chmod` calls falsified it. The enumeration is the fix: the boundaries become a declared table, each row naming its path, its direction and its declared error, with a law that drives every row through an unreadable and an unwritable state and asserts the row's own diagnosis rather than exit `70`. That closes the pair method finding **F12** adds to the relational inventory as row 21 — *a boundary's stated sentence versus the predicate it actually checks* — which was invisible for eight sprints precisely because the sentence was right. **The v1.0 tag is held until this lands** (Sprint 17): every one of the six is reachable by an ordinary user on an ordinary day, and each answers by telling that user their tool is broken. **Amended before Sprint 17 opened, after probing the mechanism (F3's rule) — and the amendment makes the rule TOTAL rather than enumerated.** A precheck alone would have repeated this decision's own mistake one level down: it enumerates the failure modes somebody thought of. Probed on 3.2.5: a write to a read-only file and a create in a read-only directory both raise a catchable `SystemExceptions.FileError` — **but reading a directory raises `SystemExceptions.WrongClass`, which escapes a handler written for `FileError`.** Enumerating the error classes is the same trap as enumerating the states. So the rule is implemented as **one chokepoint that both prechecks and translates**: `Parley.PathGuard` is the single site in Parley that performs file I/O; it prechecks so a refusal happens *before* anything is created (the atomicity `publish` and `add` need), and it wraps the primitive itself in a **broad catch that translates any error into the boundary's own declared error naming the path**. **Broad is correct here, and it does not contradict decision 52** — that decision governs a catch that *defers* to another boundary, which must name that boundary's errors and no others. This catch *owns* the diagnosis, and the block it guards contains nothing but the primitive, so there is no other error it could be swallowing. **The discriminator is whether the guarded block contains anything besides the operation.** Two consequences worth stating: the TOCTOU window stops being a user-visible gap — it can still occur and it can no longer produce a bad diagnosis — and disk-full, a read-only mount, an immutable flag and every failure mode nobody listed answer the same good sentence. **And the drift law becomes a prohibition rather than an enumeration:** *nothing outside `PathGuard` performs direct `File` I/O*, which is a far smaller and more tractable textual claim than finding every sender of a selector, and it is what finally makes relational-inventory row 21 forced. (Ruled by the operator at the Sprint 16 close-out on issue #18, on six states probed through the shipped `bin/parley`, and amended at Sprint 17 staging on the catchability probe; Doc E §4.1/§4.2, Doc F §1, extending decisions 31, 44 and 56, and bounded against 52.)

61. **The authoring boundary captures the toolchain's stream around a block its caller supplies, and the capture site performs no file I/O** — `Package.st` is executed, which makes it the one boundary where text reaches the terminal that Parley did not write: eleven lines of kernel backtrace, six of them absolute paths into Parley's own source tree, above one correct sentence. `Parley.ManifestCapture` (`src/manifest/`) rebinds the global `Transcript` to a collector, evaluates **a block the caller passes in**, restores the previous binding unconditionally in an `ensure:`, and answers the collected text as a value. **The `FileStream fileIn:` does not move into it**, and that is the ruling rather than an implementation preference. Sprint 18's staging plan described the class as swapping `Transcript` *"for the duration of one `FileStream fileIn:`"*, which reads as an instruction to put the send inside the new class; **it is rejected on two independent grounds.** First, decision 60's prohibition law searches comment-stripped source for four patterns of which `'FileStream '` carries a deliberate trailing space so that every class-side send counts, and it flags any matching class outside the eight-name census — so a `ManifestCapture` containing `fileIn:` is a **ninth** census class and the law fails, at RED, by construction. Second, it would place **the author's whole program** inside a class whose declared job is capture, which is decision 73's *precheck yes, translate no* split re-created one level up: the block a capture guards must contain the operation and nothing else, exactly as decision 52's discriminator requires of a broad catch. `ManifestFile` therefore keeps the send, keeps its seat in the census, and **the census stays at eight** — decision 60 permits a census genuinely re-derived from the property it prohibits, and this one is not re-derived because nothing about the property changed. **The portable half:** a class introduced to observe a boundary must not acquire the boundary's I/O in order to observe it, or the observer becomes a site the prohibition has to exempt. *(Numbered 61 because 61–65 and 67–71 are reserved for roadmap §2 items 2–7 and this is item 2; §8 is a log, not a sequence.)* (Ruled by the operator at Sprint 18's Gate C on issue #20, on a probe of `tests/support/PathFixtures.st:250` and `Sprint17AcceptanceTest>>testS13`; Doc B §2.2 and Doc E §3.1, bounded by decisions 52, 60 and 73.)
62. **A capture is evidence, not output — re-voice it, never echo it, and state what cannot be captured rather than chasing it** — the captured backtrace is the most valuable text at this boundary and the most dangerous to print: its own frame line carries `(<basename>:<line>)`, so Parley is presently discarding a **file and a line number** for the commonest authoring mistake there is, while the frames around it carry four absolute paths into Parley's source tree (re-probed at the Sprint 18 RED review; *six* was the staging plan's count and was wrong). Three rules, each a refusal. **On success the capture is discarded** — a manifest that loaded cleanly has nothing to report even if the toolchain muttered. **On failure Parley extracts the file-and-line anchor and composes its own sentence** in the settled `'<path>: …'` grammar; the resulting diagnosis is better than any of the seven benchmarked package managers gives for the equivalent error, which is why this is a feature and not a suppression chore. **It is never echoed verbatim**, because echoing it would move the defect rather than fix it. **Two fragments are unreachable and are therefore stated, in decision 45's shape** (finding **F8**'s standard, and decision 43's): `primError`'s `Object: <receiver>` prefix reaches **stdout** at C level and is a **bounded limitation** — it carries no frame and no Parley path, so the marker-absence law passes over it *by its stated bound* rather than by luck. **That fragment is a fragment and not a line, and this decision as first written stated its content without its terminator** (amended at the Sprint 18 RED review, on a probe): `primError` emits no trailing newline, so left alone the prefix **fuses with Parley's next output** and the operator reads `Object: nil/…/Package.st: line 2 raised an error …` — neither a line Parley composed nor one it deliberately kept, but a third thing made by the two colliding, which fails this boundary's own exit criterion on its own headline scenario. **So the fragment is terminated: when `ManifestFile` recovers a file-and-line anchor from the capture, it ends the dangling line before composing.** The predicate is *the anchor was found*, not *the capture is non-empty*, because a manifest that merely printed on its own behalf leaves no residue; `ManifestCapture` is untouched and decision 61's *it captures, the caller decides* stands. **The portable half: a stated limitation must state how the text is DELIMITED, not only what it says — an unterminated fragment is not a line you can pass over, it is a prefix on the next line you write**, and the difference is invisible until something is printed after it. The termination is also what turns the claim from substring containment into exact captured bytes; and the parser's `<path>:<line>: parse error` reaches **stderr** at C level and is **deliberately kept**, because it names the author's file and line and suppressing it would destroy information Parley cannot reconstruct. The kept line carries a stated consequence: **Parley cannot distinguish an unparseable `Package.st` from one that never sent `define:`** — on the parse path `fileIn:` returns normally, nothing is recorded and the capture is empty — so both answer the settled `no manifest defined` line naming the path, that literal is **not re-toned**, and the information separating them is already on the operator's terminal. Reopens only if a stdout/stderr capture arrives for another reason (roadmap §2 item 3's redirect is the named trigger). **The marker-absence law is asserted over captured stdout and stderr from the shipped binary, never over the `CliResult`'s composed `result lines`** — asserting over `result lines` is exactly what let eleven lines of kernel text ship past laws that deny backtraces. That **extends the reach of decision 73's prefix bound without amending it**: the same claim, checked on a wider instrument. Where the two could be read as competing, **73 governs the composition of a diagnosis line and 62 governs what may reach the terminal at all.** (Ruled by the operator at Sprint 18's Gate C on issue #20, on probes re-run 2026-08-09; **amended by the operator at the Sprint 18 RED review** — the termination clause and the corrected frame count — after the coding agent disclosed the fusion at RED rather than shipping past it, and the operator probed it rather than accepting the report; Doc B §2.2 and Doc E §3.1, extending decisions 44 and 73 and bounded by 43, 45 and 58.)
74. **A boundary that names a path other than the offending one must distinguish every shape that path can take, and the law over it drives the shape-space rather than the permission bits** — Sprint 17 gave the state-root row a deliberate rule: an operator told `<workdir>/.parley` could not be written is reading a name Parley invented, so `ensureDirectory:` names the **working directory the operator chose**. That rule is right for the state it was written for and **false** for one it never considered: a regular file at `<workdir>/.parley` — or at `<workdir>/.parley/packages` with `.parley` writable — answers `/…/f1: could not be written - check its permissions and try again` about a directory `test -w` reports **writable**, with a remedy that cannot work. Decision 58 forbids exactly that, and it was broken by the newest row in the table Sprint 17 built. **So the refusal distinguishes the two states by predicate before composing anything**, and the wrong-type state answers a line naming **the offending path itself** with a cause and a checked remedy — the shape the `parley.lock` row already carries. Neither state's exit code changes; both were and remain exit `1`, which is why Sprint 17's headline criterion held and no law failed, and why this was found only by an operator inventing states nobody had listed. **The portable half is the law, not the fix** (method finding **F13**): a chokepoint that translates *any* error makes the **error class** total and does nothing about the **set of hostile states the laws drive**, which in Sprint 17 was a list of exactly two — `unreadable` and `unwritable`. A path is not two things. The row is driven through **absent**, **already a directory**, **a regular file**, and **a wrong-type or unwritable parent**, each answering its own declared sentence — so the sprint whose thesis was *enumerating states is the trap* stops enumerating its own. *(Numbered 74 because 61–65 and 67–71 are reserved for roadmap §2 items 2–7 and this is a ruling beyond item 2's own two; §8 is a log, not a sequence.)* (Ruled by the operator at Sprint 18's Gate C on issue #20, on the Sprint 17 close-out's probe re-run; Doc E §4.1, extending decisions 58, 59 and 72 and bounded by 43.)

75. **A cleanup that runs on the unwind cannot protect a handler that runs before it — so a law over a swapped global pins the real order instead of asserting the convenient one** — Sprint 18's `ManifestCapture` restores the global `Transcript` in an `ensure:`, and the reviewed law asserted the binding was already back **inside** an `on:do:` handler for an error raised in the captured block, reasoning that a handler is where a diagnosis gets composed and printed. **That is false about this toolchain and about every conforming one.** A handler runs on top of the still-live signaling context and an `ensure:` runs on the **unwind**, so the measured order is `#blockStarted #handlerRan #stillSwapped #ensureRan` — probed at the mid-GREEN halt rather than reasoned. The coding agent halted on the failing law rather than editing a reviewed test, which is the system working. **The agent's stated ground was wrong even though its conclusion was right, and the difference is the ruling.** It reported the assertion *unsatisfiable by construction*; it is not. Catching the error inside the capture and sending `e pass` **does** restore before the outer handler — probed: `#innerRestoreRan #outerHandlerRan #restoredInHandler` — and it swallows nothing, so *swallowing* is not why it is refused. **It is refused because it wraps the author's whole program in a broad catch**, where decision 61 requires the block a capture guards to contain the operation and nothing else, and where decision 52's discriminator turns; and because re-signalling across the boundary disturbs the signalling chain that Doc E §3's `isLoading` scoping depends on, the hole Sprint 9 GREEN reopened. **The ruling: the law asserts BOTH halves of the measured order** — the swap is still live inside the handler, and the binding is back once that handler returns — rather than deleting the half that failed. Deleting it would go silent about the ordering; pinning it means the rejected catch-and-restore-early design **fails this law**, so decision 61's prohibition becomes mechanical at a second point exactly as its no-I/O law already made it mechanical at the first. **The consumer constraint is stated rather than discovered** (decision 43): any handler for an error raised inside the capture window runs with `Transcript` **still swapped and must not print**. Nothing does today — the boundary signals from `ManifestFile`'s own frame after the window has closed, and printing happens in `bin/parley-main.st` after a full unwind — so this binds future code, not present code. **The portable half: a resource released on the unwind is still held everywhere a handler can run, so a law about "it is restored by then" must name *by when*, and a test that asserts the ordering it wished for will be satisfied by exactly the implementation the design forbids.** *(Numbered 75 because 61–65 and 67–71 are reserved for roadmap §2 items 2–7, and 61, 62 and 74 are spent; §8 is a log, not a sequence.)* (Ruled by the operator at a Sprint 18 mid-GREEN halt-and-ask on issue #20, on two probes run at that halt; Doc E §3.1, extending decision 61 and bounded by 43 and 52.)

63. **A plumbing child's chatter is discarded by a redirect on the composed line; a child that is also the user's program is not** — `publish` prints five `mkdir`/`ln`/`rm`/`cd`/`zip` lines above its one composed line, leaking `/tmp/gstar-*` and the staging directory, and `install` prints an `/usr/bin/install -c` line: text on the operator's terminal that Parley did not write, which is Sprint 18's defect at the execution boundary. **The mechanism is a stdout redirect appended to the command line Parley already composes** — it buffers nothing, touches no stderr, and interpolates no user text, which is precisely why roadmap §3's split row rules it in while *output capture* stays deferred. **`exec` is carved out, and the carve-out is the ruling's substance rather than an exemption.** Probed at Sprint 19's Gate C: `exec`'s `"Global garbage collection... done"` reaches **stderr**, not stdout as the roadmap item asserted, and `gst -f <script>` alone writes nothing there — so it comes from the `gst -i -I <target>/parley.im` image load Parley composes (`ExecutionScope.st:77`) and is plumbing by origin. But `exec` spawns **one** child that is both the plumbing and the author's program, sharing **one** stderr, so silencing the fragment means either silencing the script's own error output or buffering to tell them apart — and buffering is the deferred mechanism by name. The fragment is therefore **kept and stated** in decision 45's shape. **Silencing chatter must never silence failure:** the child's exit code is still checked and the settled diagnosis still names what failed, or the redirect would manufacture the fail-wrong this project exists to prevent. **The portable half: a redirect is safe exactly when the process on the other end is yours and not the user's, and "whose process is it" is a sharper question than "which stream is it."** **Amended pre-RED, 2026-08-11 — the `exec` clause is re-ruled by decision 77:** the two-route ground above did not survive its own probe — `-g` (`--no-gc-message`) suppresses the GC chatter at the source, touching neither stream, so the fragment is no longer kept. The redirect half of this ruling and its bound stand unchanged. (Ruled by the operator at Sprint 19's Gate C on issue #21, on probes run at that gate which corrected the roadmap item's own stated premise; Doc E §1 and §4.1, bounded by 45; `exec` clause amended by decision 77.)

64. **Configuration is a file the operator owns, in Parley's own micro-format, at the project root — and an explicit flag always wins** — `--source`, `--git` and `--index` are retyped on every command, with no way to record the choice; all seven benchmarked package managers have a project-level configuration file. **Three rulings, each with a reason that is not taste.** *Format:* the settled literal micro-format under a new `#'parley-config' 1` schema (Doc B §5), read by the settled `IndexEntryReader` — **no third-party serialization, ever** (the moat, Doc B §2.4), and Parley already owns a literals-only reader with a diagnosis boundary, so a second format would mean a second reader and a second wording for one malformed file. *Location:* **`<workdir>/parley.config.st`, at the project root beside `Package.st` and `parley.lock`, and deliberately NOT under `.parley/`** — that directory is regenerable state (the store, the caches, the packages target) which an operator may delete to clean a project, and **configuration is theirs and must survive that**; the three root files then have three clear owners: the author writes `Package.st`, Parley writes `parley.lock`, the operator writes `parley.config.st`. *Precedence:* **an explicit flag always wins**, and configuration supplies the default only when no flag is given — so every settled scenario's behaviour is byte-identical and the file can only add. **`Parley.Configuration` (`src/exec/`) reads and answers values; it decides no precedence** — `CommandLine` does, because precedence is wiring and wiring is already its job. A **user-level** config is deferred with its reason: home-directory I/O, a platform question, and a second precedence layer, none of which is needed to stop the retyping. **The portable half: a configuration file belongs outside the directory the tool treats as disposable, or the tool will eventually tell the user to delete their own settings.** (Ruled by the operator at Sprint 19's Gate C on issue #21; Doc B §5 and Doc E §4.1, extending decision 57 and bounded by 43 and 56.)

65. **The configuration read is a boundary like every other, and it is a row of the table rather than an exception to it** — a new operator-editable file is a new deserialization boundary, and this project has shipped the same defect at three of them (a corrupt lock, a malformed entry, an unparseable manifest) before ruling it. So `parley.config.st` is held to the settled shape from the day it exists rather than after it fails: it must be a **regular readable file** (decision 56), it must **parse**, it must carry the **`#'parley-config' 1`** tag and a supported format version, and its **body shape** is validated before any value reaches a consumer (decision 35's lesson — a shape check that never asks whether the string means anything is the defect one level down). Each failure answers **one line naming the path, a cause, and a checked remedy** at exit `1`, never a kernel class and never exit `70`. It routes through `PathGuard` like every other file boundary, so the decision-60 census does not grow, and it becomes a declared **read** row of the boundary table with its own sentence — which means the settled table law drives it under the hostile states automatically. **The portable half: the cheapest moment to give a new boundary the diagnosis every other boundary earned is the sprint that introduces it, because that is the only moment when nothing has shipped that depends on the wrong behaviour.** (Ruled by the operator at Sprint 19's Gate C on issue #21; Doc E §4.1, extending decisions 35, 56, 59, 60 and 73.)

76. **A recovered anchor means the load failed, whatever the file managed to record** — `ManifestFile load:` mines the capture for a file-and-line anchor, terminates the stated fragment, and then checks `authoringProblems` and `recorded` in that order. A `Package.st` that sends `define:` twice, where **either** send raises, leaves `recorded` non-`nil` from the send that worked, so the anchor is **discarded and the verb exits `0`** — probed at the Sprint 18 close-out by asking what shapes a `Package.st` can take beyond the ones the scenarios drove. Doc E §3 has said *"a `Package.st` with a broken `define:` must never half-succeed"* since Sprint 9, and the ordering rules beneath that sentence govern the captured-error slot, which a `doesNotUnderstand` never reaches: `gst`'s `executeStatements` abandons the statement and continues. **So the sentence was true and the code below it did not implement it.** The ruling: **an anchor recovered from the capture is itself a failure signal, checked before `recorded`** — a manifest whose program raised is refused with the re-voiced file-and-line diagnosis, whatever else the file managed to declare. Pre-existing rather than introduced by Sprint 18, which changed only the *signal*: eleven diagnostic lines became two `Object: nil` fragments, so the sprint that removed the noise also removed the only evidence the fault had occurred. **The portable half: when a sentence in a design document has no code that can make it false, it is not a specification — it is a hope, and the test that would have caught it is the one nobody wrote because the sentence sounded settled.** (Ruled by the operator at Sprint 18's close-out and scheduled at Sprint 19's Gate C on issue #21; Doc E §3, extending decisions 44 and 62.)

77. **A ruling that says "the only routes are X and Y" is an enumeration, and it is probed like one** — decision 63 kept `exec`'s `"Global garbage collection... done"` fragment on the ground that the verb's one child shares one stderr with the author's program, so silencing the fragment meant silencing the script's own error output or buffering to tell the two apart. **The enumeration was missing a route that sits in the toolchain's own `--help`:** `-g` (`--no-gc-message`) stops the message being written at all. Probed pre-RED on the exact composed shape — `gst -g -i -I <im> --no-user-files <script>` — stderr drops from 36 bytes to **zero**, stdout is byte-identical, the exit code is unchanged, and the script's own output passes through untouched: nothing is buffered, no stream is redirected, and decision 45's exit-code pass-through is untouched. The ruling: **`ExecutionScope>>childCommandFor:`'s pinned composition gains `-g`** (a declared settled-class exception, Sprint 19), the fragment is no longer kept-and-stated, and S4 flips from asserting the fragment's presence to asserting its **absence plus the script's stderr surviving** — the half that proves the flag silenced the plumbing and not the program. Decision 63's redirect half and its bound stand unchanged, and the deferred *output capture* row is untouched: a flag that stops text being written buffers nothing. **The portable half: "the only alternatives are X and Y" is a claim shaped exactly like "this error is unreachable" — it enumerates the author's imagination rather than the tool's surface, and the probe that falsifies it is usually one `--help` away.** (Ruled by the operator at a Sprint 19 pre-RED ruling on issue #21, on a probe run 2026-08-11; Doc E §2.2, amending decision 63's `exec` clause and bounded by 45.)

78. **The redirect belongs to each composer, and two composers may each own it — a third means extract** — Sprint 19 landed decision 63's stdout tail in **two** places, `Publisher>>silencedBuildCommand` and `ExecutionScope>>silenced:`, because the rule is *the composer appends it at its own point of execution* and the only home the two composers share is `ProcessRunner` — the seam decisions 63 and 77 both leave deliberately untouched. **Moving the tail into the seam would be actively wrong, not merely tidier:** the seam also runs `exec`'s child, which is the author's program, and a redirect there would discard the script's own stdout — the exact harm decision 77 exists to avoid. So the duplication is **accepted with a named trigger** (decision 49's standard, never a date): the two definitions are pinned against **one** test oracle, `ChatterFixtures stdoutRedirectTail`, so neither can move alone, and **the trigger is a third composer appending the same tail** — at three, extract a shared composer-side helper rather than a seam-side one. Noted so the trigger is not tripped by accident: `GitIndexSource`'s pending fix is `--quiet` at the source (the decision-77 shape and the settled `curl -sfS` precedent), not a redirect, so it does **not** count toward three. **The portable half: duplication is a defect when the copies can drift, and copies that fail a shared oracle the moment either moves cannot drift — what they cost is a reader's attention, which is a smaller bill than a wrong abstraction.** (Ruled by the operator at Sprint 19's close-out on issue #21; Doc E §1, extending decisions 49 and 63 and bounded by 77.)
